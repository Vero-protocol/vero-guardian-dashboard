# Diff Engine

The Diff Engine is a dashboard component that detects **state drift** between the on-chain version of a Vero contract and the source repository — before a Guardian casts a vote. It compares ABI definitions and compiled bytecode from both sources and surfaces mismatches in a compact, auditor-ready UI.

## What it compares

The Diff Engine runs two independent checks each time its inputs change:

| Check | On-chain source | Repository source | Match condition |
|---|---|---|---|
| ABI | ABI string fetched from Horizon / Soroban | ABI string from repo build artifacts | Strings are equal after HTML sanitization and whitespace trimming |
| Bytecode | Compiled bytecode deployed on-chain | Bytecode produced by the local or CI build | Strings are equal after whitespace trimming |

Both checks run client-side in a `useEffect`, so no server round-trip is required once the strings are available.

---

## Why it matters

A deployed contract can drift from the repository if a hotfix was applied directly on-chain, a build artifact was replaced post-audit, or a dependency version changed between deployments. The Diff Engine gives Guardians a fast, verifiable signal that what they see in the repository is exactly what is running on-chain before they sign a vote.

## Props API

```tsx
import { DiffEngine } from '@/components/DiffEngine';

<DiffEngine
  onChainAbi={string}     // Required. ABI string read from the live on-chain contract.
  repoAbi={string}        // Required. ABI string from the repository build artifact.
  onChainBytecode={string} // Required. Bytecode string of the deployed contract.
  repoBytecode={string}   // Required. Bytecode string produced by the local build.
/>
```

All four props are required strings. Pass an empty string `""` if a value is unavailable — the component handles it gracefully and will report a mismatch.

Full TypeScript type:

```ts
export interface DiffEngineProps {
  onChainAbi: string;
  repoAbi: string;
  onChainBytecode: string;
  repoBytecode: string;
}
```

## Running the Diff Engine

### Basic usage

Import the component and pass the four comparison strings. In the simplest case you can pass hardcoded strings to verify the UI renders correctly:

```tsx
import { DiffEngine } from '@/components/DiffEngine';

export default function AuditPage() {
  return (
    <DiffEngine
      onChainAbi='[{"type":"function","name":"cast_vote"}]'
      repoAbi='[{"type":"function","name":"cast_vote"}]'
      onChainBytecode="0xdeadbeef"
      repoBytecode="0xdeadbeef"
    />
  );
}
```

### Fetching inputs from real sources

In practice you will retrieve the on-chain values from Horizon or the Soroban RPC, and the repository values from your build output. A typical pattern:

```tsx
import { useState, useEffect } from 'react';
import { DiffEngine } from '@/components/DiffEngine';

export function ContractAuditPanel({ contractId }: { contractId: string }) {
  const [onChainAbi, setOnChainAbi] = useState('');
  const [onChainBytecode, setOnChainBytecode] = useState('');

  // Fetch on-chain state from Soroban RPC
  useEffect(() => {
    async function load() {
      const rpc = process.env.NEXT_PUBLIC_SOROBAN_RPC_URL ?? 'https://soroban-testnet.stellar.org';
      const res = await fetch(`${rpc}/contracts/${contractId}/abi`);
      const data = await res.json();
      setOnChainAbi(JSON.stringify(data.abi));
      setOnChainBytecode(data.bytecode);
    }
    load();
  }, [contractId]);

  // Repository ABI and bytecode are imported at build time from local artifacts
  // (e.g. generated by stellar contract build or soroban contract inspect).
  const repoAbi = JSON.stringify(require('@/artifacts/vero_contract.abi.json'));
  const repoBytecode = require('@/artifacts/vero_contract.bytecode.txt') as string;

  return (
    <DiffEngine
      onChainAbi={onChainAbi}
      repoAbi={repoAbi}
      onChainBytecode={onChainBytecode}
      repoBytecode={repoBytecode}
    />
  );
}
```

The component renders a loading placeholder (`"Loading diff engine..."`) while `result` is being computed, so it is safe to mount before the on-chain fetch resolves.

## Reading the output

### Overall drift banner

The banner at the top of the panel gives the immediate verdict:

| Banner | Meaning |
|---|---|
| 🟢 **On-chain state matches repository version perfectly.** | Both ABI and bytecode are identical. No action required. |
| 🔴 **State drift identified. Auditor-ready report generated.** | At least one check failed. Review the detail cards below before voting. |

### ABI comparison card

Shows whether the contract's public interface (function signatures, argument types, return types) matches between the two sources.

- **Match** — the sanitized ABI strings are identical. The function surface has not changed.
- **Mismatch** — the ABI differs. A function may have been added, removed, or renamed, or an argument type may have changed. Do not vote until the discrepancy is understood and resolved.

### Bytecode comparison card

Shows whether the compiled binary matches.

- **Match** — the deployed bytecode is byte-for-byte identical to the repository build.
- **Mismatch** — the binary differs. This may mean a dependency version changed, a build flag was toggled, or the contract was patched directly on-chain without a corresponding repository commit. Treat this as a hard blocker for Guardian approval.

When both cards show **Mismatch**, the drift is severe — the contract's interface and implementation both diverge from the repository.

---

## Security model

All comparison inputs are treated as untrusted strings from external sources. Before comparison, ABI strings are passed through `sanitizeForComparison`, which:

- Strips all HTML and `<script>` tags using a repeated-pass loop so nested patterns like `<<script>script>` cannot survive a single replacement.
- Trims surrounding whitespace.

Bytecode strings are whitespace-trimmed only. The component renders sanitized values as React text nodes; `dangerouslySetInnerHTML` is never used.
